# pccs-color-palette

PCCS（日本色研配色体系）を使ったカラーパレット / カラーピッカー。Next.js 製で、Vercel にそのままデプロイできます。

- 中央に HSB カラーピッカー（横軸 = 彩度 S、縦軸 = 明度 B）と、それを囲む色相環（0° = 赤が上、時計回り）
- **ピッカーをクリック**すると、その色を含む PCCS の区画（明度 ±0.25 × 彩度 ±0.5s）を白線で囲んで表示
  （両端は開いた区画: 明度 9.5 は「9.5 以上」、1.5 は「1.5 以下」、9s は「9s 以上」。彩度 0.5s 未満は無彩色 `n`）
  - 「クリックした色の区画を表示」を OFF にすると、クリックしても囲んでいる範囲は変わらない（選択色だけが変わる）
- 右パネル
  - **PCCS 明度・彩度・トーン**: 選択色の色相における PCCS の明度（縦 9.5〜1.5）× 彩度（横 n, 1s〜9s）の全マスを実際の色で塗った表
    （その色相の PCCS トーンマップ）。トーンの境界線と記号を表示し、選択中の区画・トーンを白枠で囲む。
    - マスをクリック: その区画（明度 ±0.25 × 彩度 ±0.5s。両端は開いた区画）を選択
    - トーン記号をクリック / マスをダブルクリック: そのトーン全体を選択
    - マウスを乗せる: そのマス・トーンの範囲をピッカー上にプレビュー
    - キーボード: 矢印キーで区画を移動、Enter でその区画のトーン全体を選択
    - ◥ = sRGB 外（近似色）、○ = 選択色の推定位置
  - 明度帯・彩度帯の境界線（ピッカー上の点線）は、選択中の区画またはトーンの明度・彩度の幅に対して描画
  - **選択色**: HEX / RGB / HSB と PCCS 表記・トーン

| 記号 | 名前 | 記号 | 名前 |
| --- | --- | --- | --- |
| v | 純色 (vivid) | p | 薄い (pale) |
| b | 明るい (bright) | p+ | 薄い＋ (pale plus) |
| s | 強い (strong) | ltg | 明るい灰み (light grayish) |
| dp | 深い (deep) | g | 灰み (grayish) |
| lt | 浅い (light) | dkg | 暗い灰み (dark grayish) |
| lt+ | 浅い＋ (light plus) | sf | 柔らかい (soft) |
| d | 鈍い (dull) | dk | 暗い (dark) |

トーンは Kobayashi & Yoshiki (2001) の関係式（`pccs` ライブラリと同じ）で求めます。
トーン座標 `t = l − (0.25 − 0.34·√(1 − sin((h − 2)π/12)))·s` を使い、(s, t) 平面で最も近いトーン中心を選びます。
中央値は同じ式の逆算で、ライブラリと同じく 0.5 刻み（偶数丸め）にしています。

### sRGB 外の色の扱い（OKLCH による近似）

PCCS には画面（sRGB）で表示できない鮮やかな色が多く含まれます（例: 青緑の v / s / dp は 4s 程度までしか sRGB に収まりません）。
そうした色は **OKLCH で明度と色相を保ったまま彩度（chroma）だけを下げて** sRGB に収めて表示し、近似であることを `≈` で示します。

- PCCS マップの各マスの色: sRGB 外のものは近似色で表示し、右上の三角（◥）で示します。
- ピッカー上の範囲: 彩度を下げた色は必ず sRGB の境界、つまりピッカーの上端（B = 100%）か右端（S = 100%）に乗ります。
  そこで境界上の各点から OKLCH の彩度を上げていく半直線をたどり、選択中の PCCS 値を通る点を「sRGB 外の色の近似位置」として、
  端に沿った白黒の破線帯とラベルで表示します（`src/lib/gamutEdge.ts`、計算は Web Worker 内で実行）。
- 選択色がその近似位置にあるときは、選択色の欄にもその旨を表示します。

## PCCS 値の求め方

PCCS の明度・彩度は人間の視感評価に基づく尺度なので、RGB や HSB の値からは計算していません。

1. `scripts/export_pccs.py` が Python の [`pccs`](https://pypi.org/project/pccs/) ライブラリで全パターン
   （24 色相 × 明度 17 段階 × 彩度 9 段階 = 3672 色 + 無彩色 17 色）をマンセル値に変換します。
   変換式は Kobayashi & Yoshiki (2001)「PCCS トーン・PCCS 色属性・マンセル色属性の数理的関係」です。
2. マンセル値は、視感実験に基づくマンセル再表記データ（colour-science）で xyY（C 光源）に変換し、
   Bradford 変換で D65 に順応させて CIELAB / sRGB を得ます。
3. ブラウザ側（`src/lib/pccs.ts`）では、この参照表を CIELAB 上で逆引きします。
   - 明度: PCCS 明度 = マンセル明度（輝度のみの関数）なので、無彩色スケールから補間
   - 色相・彩度: 各明度面で「色相 × 彩度」の格子セルを探し、逆双線形補間で求める

出力ファイル:

| ファイル | 内容 |
| --- | --- |
| `data/pccs-patterns.json` | 全パターンの詳細（PCCS 表記、トーン、マンセル値、xyY、XYZ、CIELAB、sRGB、HEX、sRGB 色域内かどうか） |
| `src/data/pccs-lab.json` | アプリが使う軽量版（CIELAB のみ） |

注意点:

- マンセル再表記の範囲外になる高彩度の組み合わせ（75 パターン）は `color: null` になります。アプリではその部分を線形外挿で補っています。
- `pccs` ライブラリはマンセル値を 0.5 刻みに丸めて返します（表記用）。色の計算には、同じ関数を丸めなしで呼んだ値を使っています（`munsellSpecUnrounded`）。丸めた表記は `munsell` に入っています。
- `pccs` 0.2a3 は古い colour-science の API 名を参照しているので、スクリプト内で互換用のエイリアスを設定しています。

## 開発

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # 参照パターンの再現テスト (vitest)
npm run build
```

参照データの再生成（[uv](https://docs.astral.sh/uv/) が必要）:

```bash
npm run export:pccs
```

## デプロイ

Vercel にリポジトリをインポートするだけで動きます（フレームワークは Next.js が自動検出されます。Python は実行時には不要です）。
